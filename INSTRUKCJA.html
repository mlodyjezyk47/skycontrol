OD PIERWSZEGO KLIKNIĘCIA DO WŁASNEGO LINKU

Gotowe. Możesz startować.

Ten projekt jest kompletny. Nie musisz pisać kodu, instalować programów dla programistów ani płacić za hosting. Poniżej znajdziesz całą instrukcję.

1. Uruchom stronę na komputerze

  1. Pobierz plik SkyControl.zip i znajdź go w folderze „Pobrane”.
  2. Rozpakuj archiwum. W Windows kliknij je prawym przyciskiem myszy i wybierz „Wyodrębnij wszystkie…”, a następnie „Wyodrębnij”. Na Macu kliknij plik ZIP dwa razy.
  3. Otwórz rozpakowany folder SkyControl. Znajdziesz w nim m.in. index.html, styles.css i app.js.
  4. Kliknij dwa razy index.html. Strona otworzy się w Twojej domyślnej przeglądarce. Jeżeli otworzy się edytor tekstu, kliknij plik prawym przyciskiem → „Otwórz za pomocą” → Chrome, Edge, Firefox lub Safari.
  5. Gotowe! Wybierz nowy status dowolnego rejsu i odśwież stronę. Zmiana powinna pozostać.

Nie otwieraj strony bezpośrednio wewnątrz archiwum ZIP. Najpierw je rozpakuj. Wszystkie pliki projektu muszą pozostać razem w tym samym folderze. Do działania strony nie potrzebujesz internetu.

Otwórz SkyControl →

2. Poznaj panel

  • Zegar i data: pokazują aktualny czas w Warszawie. Zegar aktualizuje się co sekundę.
  • Kolorowe statusy: bursztynowy to „Planowany”, niebieski to „W trakcie”, zielony to „Zakończony”. Kliknij kolorowe pole przy rejsie, aby zmienić status.
  • Wyszukiwarka: wpisz np. „Londyn”, „LO281”, „Paryz”, „LHR”, nazwę linii albo bramkę. Polskie znaki nie są wymagane. Przycisk × czyści wpis.
  • Filtry: wybierz „Wszystkie”, „Planowane”, „W trakcie” lub „Zakończone”. Filtr i wyszukiwarka działają jednocześnie. Aby wrócić do pełnej listy, wyczyść wyszukiwarkę i wybierz „Wszystkie”.
  • Sortowanie: kliknij nagłówek „Odlot”, aby odwrócić kolejność godzin.
  • Szczegóły: strzałka na końcu wiersza pokazuje informacje o rejsie. Tam również możesz zmienić status.
  • Liczniki i wykres: przeliczają się automatycznie po każdej zmianie. Zawsze pokazują wszystkie loty, także podczas wyszukiwania.
  • Motyw: przycisk słońca/księżyca w prawym górnym rogu zmienia wygląd na jasny lub ciemny.
  • Dziennik operacji: pokazuje 30 ostatnich zmian statusów, wraz z czasem ich wykonania.
  • Eksportuj CSV: pobiera aktualne zestawienie wszystkich 10 lotów. Plik można otworzyć w Excelu, LibreOffice Calc lub zaimportować do Arkuszy Google. Jeśli program pyta o ustawienia, wybierz UTF-8 i separator „średnik”.
  • Telefon: menu otworzysz przyciskiem ☰ w lewym górnym rogu. Tabelę można przesuwać palcem w bok, aby zobaczyć statusy i szczegóły.
  • Klawiatura: klawisz Tab przechodzi między przyciskami. „/” przenosi do wyszukiwarki. Escape zamyka okno lub menu, a w wyszukiwarce czyści wpis.

To przykładowy panel, a nie połączenie z systemem lotniska. Numery, godziny, bramki i statusy są fikcyjne. Loty nie zmieniają statusów samoczynnie ani nie resetują się następnego dnia.

3. Opublikuj bezpłatnie na GitHub Pages

Potrzebujesz bezpłatnego konta GitHub. Całość zrobisz w przeglądarce, bez terminala i bez pisania kodu.

  1. Wejdź na github.com. Zaloguj się lub wybierz Sign up, aby założyć konto. Jeśli GitHub poprosi o potwierdzenie adresu e-mail, wykonaj ten krok.
  2. Otwórz github.com/new, czyli formularz tworzenia repozytorium. Repozytorium to po prostu folder projektu w internecie.
  3. W polu Repository name wpisz skycontrol. Wybierz Public — publiczne repozytorium umożliwia bezpłatne korzystanie z GitHub Pages w planie Free. Włącz opcję Add a README file (w niektórych wersjach interfejsu „Add README”) i kliknij Create repository.
  4. Na stronie nowego repozytorium kliknij Add file → Upload files. Na wąskim ekranie „Add file” może być schowane pod przyciskiem „+”.
  5. Otwórz rozpakowany folder SkyControl na komputerze. Przeciągnij jego pliki do okna przesyłania w GitHub: index.html, styles.css, app.js, favicon.svg i INSTRUKCJA.html. Możesz też dodać README.md — zastąpi początkowy opis.
  6. Na dole strony kliknij Commit changes (a jeśli pojawi się dodatkowe okno — potwierdź przyciskiem o tej samej nazwie). To zapisuje pliki w repozytorium, zwykle w gałęzi main.
  7. Sprawdź, czy index.html jest widoczny od razu na głównej liście plików repozytorium. Nie powinien być schowany w dodatkowym folderze „SkyControl”. Nie przesyłaj samego pliku ZIP.
  8. W górnym menu repozytorium kliknij Settings, a następnie wybierz Pages w menu po lewej stronie. Na małym ekranie możesz potrzebować rozwinąć menu.
  9. W sekcji Build and deployment przy Source wybierz Deploy from a branch. W części Branch wybierz main oraz /(root), po czym kliknij Save. Jeśli Twoja gałąź ma inną nazwę, wybierz tę, w której widzisz pliki projektu.
  10. Poczekaj kilka minut i odśwież Settings → Pages. GitHub pokaże link oraz przycisk Visit site. Pierwsza publikacja może potrwać do około 10 minut.
  11. Twój adres będzie zwykle wyglądać tak: https://TWOJ-LOGIN.github.io/skycontrol/. Zastąp „TWOJ-LOGIN” nazwą swojego konta lub po prostu skopiuj gotowy adres z GitHub. Wyślij go sobie na telefon i otwórz w zwykłej przeglądarce.

Opublikowana strona i pliki publicznego repozytorium są dostępne dla każdego, kto do nich dotrze. W projekcie są wyłącznie dane przykładowe. Nie potrzebujesz własnej domeny, płatnej usługi ani bazy danych.

4. Gdzie zapisują się zmiany?

Strona korzysta z localStorage, czyli małej pamięci przeglądarki. Zapisuje statusy lotów, ostatnie 30 zmian i wybrany motyw. Odświeżenie strony nie usuwa tych ustawień.

  • Każde urządzenie ma osobny zapis. Zmiana na komputerze nie pojawi się na telefonie. Różne przeglądarki również mają osobne zapisy.
  • Wersja otwarta z pliku na komputerze i wersja pod linkiem GitHub Pages mają osobne dane.
  • Tryb incognito/prywatny może usunąć zapis po zamknięciu okna. Wyczyszczenie danych witryny także usuwa zapis.
  • Jeśli przeglądarka blokuje zapis, panel wyświetli ostrzeżenie i nadal będzie działać, ale zmiany będą dostępne tylko w bieżącej sesji.
  • Obsługa pamięci dla plików otwieranych bezpośrednio z dysku może różnić się między przeglądarkami. Jeśli zapis lokalny nie działa, otwórz projekt pod linkiem GitHub Pages. Nie przenoś folderu projektu, jeśli chcesz zachować dotychczasowy zapis wersji lokalnej.

5. Gdy coś nie działa

  • Widzę tekst zamiast strony: otwórz index.html przeglądarką, nie edytorem tekstowym.
  • Strona nie ma kolorów lub nie pokazuje lotów: rozpakuj ZIP. Sprawdź, czy styles.css i app.js leżą obok index.html. W przeglądarce musi być włączony JavaScript.
  • GitHub pokazuje błąd 404: sprawdź ustawienia Pages, gałąź i /(root). Sprawdź, czy plik nazywa się dokładnie index.html i leży na głównej liście plików. Zaczekaj do 10 minut. W zakładce Actions można sprawdzić, czy publikacja się zakończyła.
  • Nie widzę zmian po przesłaniu nowszych plików: zaczekaj na zakończenie publikacji, a następnie odśwież stronę. Na komputerze możesz użyć Ctrl+F5 lub na Macu Cmd+Shift+R.
  • Nie widzę statusu na telefonie: przesuń tabelę poziomo. Możesz też obrócić telefon.

Aby opublikować później nową wersję, ponownie użyj Add file → Upload files, prześlij zmienione pliki o tych samych nazwach i kliknij Commit changes. GitHub Pages zaktualizuje stronę automatycznie.
